# 阶段 8 安全审查

审查范围为项目源码、隔离 SQLite 和 Windows 本机课堂服务。重点覆盖认证、三角色对象范围、Web 响应、输入边界、审计及配置。检查发现的课堂运行和防御缺口已修复，其余风险按运行场景记录。

## 已修复发现

| 编号 | 优先级 | 发现与影响 | 修复与验证 |
| --- | --- | --- | --- |
| S8-01 | 高 | 默认开发入口开启 Flask 调试。借用开发配置做课堂运行会继承调试行为 | 新增 demo 配置，启动只绑定 127.0.0.1、随机签名密钥、限制本机 Host、关闭调试器和重载，正式 HTTPS 配置拒绝经本地入口启动。以 FLASK_DEBUG=1 实际启动，验证监听与控制台路径。[启动入口](../source/学生管理系统源码/run.py#L13) · [回环证据](stage8_backup_restore.json) |

## 现有防御的回归结果

| 范围 | 核验结果 |
| --- | --- |
| 认证 | Werkzeug 哈希，统一登录失败反馈，POST 退出，改密和管理员重置后的凭据版本失效。账号停用、角色或绑定变更后旧会话失效，原状态恢复也无法复用。30 分钟绝对时限与登录清旧会话通过测试 |
| 对象级授权 | 管理员全局，教师按当前班级和授课关系分别授权，学生仅本人。URL、表单的 student_id、teacher_id、class_id、course_id、created_by、role_id 不扩大权限。跨班、跨课程、历史学期写及越权统计拒绝 |
| CSRF 与 Cookie | 写操作受 Flask-WTF 保护，缺失及非法 Token 被拒绝。真实本机登录 Cookie 包含 HttpOnly、SameSite=Lax。HTTPS 配置设置 Secure |
| SQL 与 HTML | 服务使用 SQLAlchemy 参数化查询，搜索使用转义通配符。用含普通标点的输入核对字面查询，验证 HTML 标签转义及模板标记保持文本。登录回跳仅允许校验后的本地路径 |
| 输入与错误 | 非法类型、日期、分页边界及存储失败有覆盖。应用通用错误页不展示底层异常参数，浏览器无未处理错误 |
| 审计与日志 | 凭证不出现在会话、普通页面或被检查日志。历史审计需经过实体字段白名单和递归清理。审计只读访问、追加保护及事务回滚均保留 |
| 外部通信 | 本机浏览器流程无外部 HTTP 请求。模拟通知只创建本地记录，原有测试禁止模拟路径调用网络 |

## 剩余风险及边界

- 签名 Cookie 的普通退出清理当前客户端会话。已复制 Cookie 的全局即时撤销依赖密码、角色、档案绑定、账号状态变化或会话到期。服务端集中撤销与登录限流适合随正式部署评审。
- 正式 HTTPS 的证书、代理可信配置、访问管控和外部依赖漏洞库扫描属于独立验收。此次 pip check 验证锁定依赖兼容性。
- SQLite 文件和备份包含敏感业务记录。生产保管依赖文件权限与加密介质。恢复演练使用合成数据及独立实例。
