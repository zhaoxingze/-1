# 阶段 4B 教师档案授权

以下规则是阶段 4B 新增设计决策。权限依据当前数据库关联，阶段 3 的本人资料和阶段 4A 的管理员接口沿用各自规则。

| 操作 | 管理员 | 班主任 | 任课教师 | 学生 |
| --- | --- | --- | --- | --- |
| 学生档案管理 | 全局管理入口 | 本班只读基本资料，限改电话和住址 | 当前授课课程名单中只读学号、姓名 | 阶段 3 本人最小资料 |
| 家长档案 | 全局管理入口 | 本班家长姓名、关系、电话、邮箱、主要联系人标记，只读 | 禁止 | 禁止 |
| 修改学号、班级、学籍、归档或新增学生 | 原管理入口 | 禁止 | 禁止 | 禁止 |
| 账号状态与物理删除 | 维持原阶段的接口边界 | 禁止 | 禁止 | 禁止 |

班主任详情展示学号、姓名、当前班级、电话和住址。一个教师可以同时任班主任和授课教师。每项操作分别判断来源关系，任课名单中的学生只有同时属于其班级时才获得班主任操作权限。

| 决策编号 | 4B 采用的规则 | 后续待定 |
| --- | --- | --- |
| A-04 | 班级范围由 `SchoolClass.homeroom_teacher_id` 与 `Student.class_id` 决定。课程身份名单由 `Course.teacher_id` 和已有 `Enrollment` 决定 | 成绩、考勤、奖惩、沟通记录等能力独立决定 |
| A-05 | 班主任限改本班学生 `phone` 和 `address` | 无其他档案编辑授权 |
| A-10 | 每次按当前任课教师判断，原任课教师失去该课程名单权限 | 历史任教关系、成绩访问与可编辑学期 |
| A-21 | 每次按当前班主任和分班判断。已归档或非在读仍按当前关联，不引入额外状态门槛 | 转班历史和历史统计 |
| A-22 | 任课名单按课程已有选课去重。当前模型无“当前学期”配置，因此名单不猜测学期，仅展示学号和姓名 | 新增选课候选范围、当前学期选取 |

教师身份来自当前有效 User 绑定的 Teacher。后端验证账号、角色及绑定，从数据库构造班级和课程范围。路径中的班级、学生、课程 ID 仅标识候选资源。未知 action、无效 ID 和范围外对象统一拒绝。分页查询先应用授权过滤，任课名单使用只选取学号和姓名的 SQL 投影。

`get_teacher_scope` 提供当前教师绑定和范围查询。单对象判断由 `can_view_student`、`can_edit_student_contact`、`can_view_parent_contact` 和 `require_teacher_student_access` 共享。任课身份查询 action 必须指定受授权的课程。原 `can_access_student_resource` 保持阶段 3 语义，教师使用新入口。

编辑使用 POST 和 CSRF。表单拒绝额外字段及重复键，服务再次执行白名单和原字段长度校验。SQLite 在写入前取得写锁并按当前关系重新授权，更新和 `AuditLog` 在同一事务。快照限电话和住址，操作者从会话取 User 主键，提交失败回滚。沿用原数据库结构和七个 Blueprint。
