## 1 范围与目标

系统服务于学生综合信息集中管理的课程设计，覆盖六类业务：学生信息、课程成绩、考勤、奖励与处分、家长联系、管理员权限。班级、教师和家长是支撑档案；首页统计是这些模块的聚合查询。

| 范围内 | 范围外 |
| --- | --- |
| 本地 Web 登录、退出、角色权限 | 多校区、多租户 SaaS |
| 学生、班级、教师、家长档案 | 教育局或学籍平台对接 |
| 课程、按学期选课、成绩录入与查询 | 在线考试、自动阅卷 |
| 考勤、奖惩、家长沟通及模拟通知 | 真实短信和邮件网关 |
| 首页概览、成绩和考勤基础统计 | 复杂 BI、数据仓库 |
| SQLite 持久化、Windows 本地部署 | 云端高可用和分布式部署 |

单校区、单机或局域网演示是原案场景假设 A-01。家长只是被联系的信息对象，无家长账号、登录端或自主操作用例。没有学生自主选课、教师自行创建课程、学生自行修改资料、家长在线回复、审批流等已确认需求。

## 4 三角色权限边界

### 4.1 授权的共通条件

仅 `admin`、`teacher`、`student` 三个角色；一个 User 关联一个 Role。管理员不关联教师或学生档案；教师账号只关联 Teacher；学生账号只关联 Student。教师、学生账号缺失正确关联时不得进入相应业务范围。角色代码不表示固定 role_id 数值。

访问须同时满足：账号有效、功能角色允许、目标对象在授权范围、所有关联对象匹配。范围不能由请求参数声明。未登录页面请求跳转登录页，登录后无权限返回 403（原案阶段 3）；最小学生资料路由先授权再查询：无权限（含无权且不存在的ID）403，授权后找不到对象404，不通过错误信息泄露他人数据。

停用账号不得继续执行受限操作。阶段 2 明确学生归档不改变 User.is_active；不因毕业或休学擅自禁止历史查询。阶段 3 已提供角色与最小对象级授权基础设施；审计查询仅可在后续实现管理员授权后开放，当前无审计查询路由。

### 4.2 权限矩阵

“待定”表示未获已确认的授权；后续不得直接开放。管理员“全局”仍受字段校验、关联完整性和历史保留约束。

| 操作 | 管理员 | 教师 | 学生 |
| --- | --- | --- | --- |
| 登录、退出、修改本人密码 | 允许 | 允许 | 允许 |
| 创建、改角色、关联档案、停用账号、重置他人密码 | 全局 | 禁止 | 禁止 |
| 学生新增、学号/班级/学籍维护、归档 | 全局 | 禁止 | 禁止 |
| 学生档案查询 | 全局 | 4B 班主任本班基本资料。任课教师所授课程名单仅学号和姓名 | 阶段3本人最小资料 |

| 班级和教师档案维护 | 全局 | 禁止；可查看负责范围内必要信息 | 禁止 |
| 家长档案维护和查询 | 全局 | 4B 班主任当前本班家长联系方式只读 | 禁止 |

### 4.3 教师数据范围的可实现边界

原案能直接支撑两个关系：`SchoolClass.homeroom_teacher_id == current_user.teacher_id` 的班级、`Course.teacher_id == current_user.teacher_id` 的课程。任意班级的任课教师关系、代课、协同教学和按学期授课关系均没有专门表。

4B 按操作分别检查当前班主任和授课教师关系。任课身份名单访问不授予本班详情、联系方式编辑或家长查看。阶段 5 依据课程归属和配置学期授权成绩，依据课程归属、班主任关系和配置学期授权新增选课。阶段 6 的考勤、奖惩、家长联系及通知均按班主任与学生当前班级关系授权。[教师权限设计](stage4b_permissions.md) · [阶段 6 决策](stage6_decisions.md)

### 5.1 UC-02 新增学生

前置条件：已登录且账号有效的管理员；字段按阶段2数据库与阶段4A校验处理，班级可空、非空时必须存在。

1. 管理员进入新增表单，填写学号、姓名、性别、出生日期、班级、联系方式、入学日期和学籍状态等。
2. 路由检查会话、管理员权限和 CSRF，Service 再检查调用者及输入、关联班级。
3. 校验必填、格式与学号唯一性。预查询有利于提示，最终仍由数据库 UNIQUE 处理竞争写入。
4. 校验通过后通过 ORM 在事务中保存；提交成功才返回成功并刷新列表。
5. 字段错误或学号已存在时返回字段反馈；提交冲突或数据库错误时回滚，不返回虚假成功。

后置条件：成功新增一条 Student；失败时没有新增学生记录。输入 `age` 不形成持久化字段。新增学生是否自动建账号没有既定要求，不能隐含为自动操作。

### 5.2 UC-05 录入成绩

前置条件为有效管理员，或当前负责目标课程且该记录在 ACTIVE_SEMESTER 内的授课教师。目标 Enrollment 必须存在。

用户筛选课程及学期，选择获授权的选课记录并输入两项成绩。服务校验有限数值和 0–100 边界，计算总评，在事务内再次授权并写入成绩和审计。缺分、非数字或越界退回表单，越权返回 403。新选课三项成绩初值均为 NULL，查询时显示“未评分”。
